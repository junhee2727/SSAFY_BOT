# 데이터 저장 및 복구

## 목적

SQLite로 기능별 상태를 보존하고 연결 중단이나 프로세스 재시작 후 처리를 이어간다.

기준 문서: [전체 구현 계획](../plan.md)

## 저장 대상

| 데이터 | 용도 |
| --- | --- |
| 할 일과 마감·완료 상태 | 할 일 관리와 마감 알림 |
| 메일 식별자와 수집 기준 | 신규 메일 판별과 중복 처리 방지 |
| 뉴스레터 정보와 요약 | 요약 재사용과 조회·전달 |
| 처리한 DM과 마지막 처리 지점 | 명령 중복 실행 방지와 누락 DM 복구 |
| 발송 대기·완료 기록과 발송 식별자 | 알림·뉴스레터 재시도와 발송 결과 대조 |

## 동작과 요구사항

- Node.js 단일 프로세스에서 로컬 SQLite를 사용한다.
- 재시작 후에도 할 일, 메일 처리, 요약, DM 처리, 발송 상태를 유지한다.
- 연결 복구 시 마지막 처리 지점 이후 DM을 조회할 수 있도록 한다.
- PC가 꺼져 놓친 마감 알림과 뉴스레터 발송을 복구할 수 있도록 한다.
- 불명확한 발송 결과는 최근 봇 게시물과 발송 식별자를 대조한 뒤 재시도한다.
- 로컬 DB는 Git 추적에서 제외한다.

## 의존 기능

- [매터모스트 연동](매터모스트연동.md): 누락 DM 조회와 발송 결과 대조.
- [마감 알림](마감알림.md), [뉴스레터 전달](뉴스레터전달.md): 누락 발송 복구.
- [설정 및 실행](설정및실행.md): 실행 환경과 Git 제외 규칙.

## 검증 기준

- 프로세스 재실행 후 저장 데이터가 유지된다.
- 같은 메일과 DM을 재수신해도 처리 기록을 활용한다.
- 요약 완료 기록을 재사용한다.
- 발송 대기와 완료 상태를 구분해 누락 항목을 복구한다.
- 네트워크 오류로 결과가 불명확한 경우 대조 후 재시도한다.
