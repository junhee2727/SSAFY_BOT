# Mattermost 개인 비서 봇 구현 계획

## 1. 목표와 구성

내 PC에서 실행하는 **TypeScript/Node.js 봇**을 만든다. Mattermost DM으로 할 일을 관리하고, 네이버 이메일 뉴스레터를 **SSAFY GMS의 `gemini-3.5-flash`로 요약해 매일 오전 9시**에 받는다.

- Node.js 단일 프로세스와 SQLite를 사용한다.
- Mattermost WebSocket으로 DM을 수신하고 REST API로 응답한다.
- 한국 시간(`Asia/Seoul`)을 기준으로 예약 작업을 실행한다.
- 첫 버전은 개인 사용자 1명만 지원한다.
- 추가 정보 제공 기능은 이후 확장할 수 있도록 모듈을 분리한다.

## 2. 사용자 기능

### 할 일 관리와 DM 명령

| DM 명령 예시 | 동작 |
| --- | --- |
| `도움말` | 명령과 사용 예시 안내 |
| `할일 추가 보고서 제출 /마감 2026-09-21 18:00` | 마감이 있는 할 일 등록 |
| `할일 추가 알고리즘 공부` | 마감 없이 등록 |
| `할일 목록` | 미완료 할 일과 번호 표시 |
| `할일 완료 3` | 해당 번호 완료 처리 |
| `할일 삭제 3` | 해당 번호 삭제 |
| `뉴스레터` | 저장된 최신 뉴스레터 요약 조회 |
| `상태` | 메일 수집·요약·예약 발송의 최근 성공과 오류 표시 |

- 마감 시각에 미완료 항목을 한 번 알린다.
- PC가 꺼져 놓친 마감 알림은 재실행 시 묶어서 전달한다.
- 명령은 정해진 문법으로 처리한다. 잘못된 날짜나 번호에는 수정 방법을 안내한다.

### 뉴스레터 수집과 전달

- 네이버 IMAP을 5분마다 확인한다.
- 설정 파일에 지정한 메일함과 발신자 허용 목록으로 수집 대상을 제한한다.
- 기본 메일함은 `INBOX`이며, 발신자를 등록하기 전에는 수집하지 않는다.
- 최초 실행 이전 메일은 자동 수집하지 않고, 이후 수신한 대상 메일부터 처리한다.
- 메일별로 제목·발신자·한국어 핵심 요약 3~5개 항목·본문에서 추출한 원문 링크를 저장한다.
- 오전 9시에 아직 발송하지 않은 요약을 묶어 DM으로 보낸다. 새 항목이 없으면 발송하지 않는다.
- 오전 9시에 PC가 꺼져 있었다면 재실행 후 누락된 항목을 한 번에 전달한다.

## 3. 연동과 내부 구현

### Mattermost와 저장소

- 본인 아이디·비밀번호로 로그인하고, 로그인 응답의 사용자 ID로 ‘나와의 대화’ DM만 처리한다.
- 인증정보는 `.env`에 설정한다. 비밀번호 인증만 사용하며 로그인 세션 토큰은 메모리에서 관리한다.
- 프로그램의 응답과 이미 처리한 메시지를 제외한다. 사용자와 프로그램의 작성자 ID가 같으므로 발송 ID나 게시물 속성으로 구분한다.
- 연결이 끊기면 재접속하고 마지막 처리 지점 이후 DM을 조회한다.
- SQLite에 할 일, 메일 식별자, 요약, 처리한 DM, 발송 대기·완료 기록을 저장한다. 재시작 후에도 상태를 유지한다.
- 네트워크 오류로 발송 결과가 불명확하면 최근 봇 게시물과 발송 식별자를 대조한 뒤 재시도해 중복을 줄인다.

### 네이버 메일

- IMAP은 TLS로 연결하고 읽기 상태·폴더·메일 내용을 변경하지 않는다.
- HTML 메일은 텍스트로 정리하며 첨부파일과 원격 이미지는 가져오지 않는다.
- 수집 대상 뉴스레터 본문만 GMS 요약에 사용한다.

### SSAFY GMS 요약

사용자가 제공한 호출 예시를 기준으로 아래 API를 사용한다.

```text
POST https://gms.ssafy.io/gmsapi/generativelanguage.googleapis.com/v1beta/models/gemini-3.5-flash:generateContent
Content-Type: application/json
x-goog-api-key: <GMS_KEY>
```

요청 본문 형식:

```json
{
  "contents": [
    {
      "parts": [
        {
          "text": "요약 지시와 뉴스레터 본문"
        }
      ]
    }
  ]
}
```

- Node.js의 `fetch`로 GMS를 호출한다. 모델명과 엔드포인트는 설정 가능하게 한다.
- 뉴스레터 본문은 요약할 데이터로 취급하고, 본문 안의 지시를 실행하거나 도구를 호출하지 않는다.
- 긴 본문은 나누어 요약 후 합친다.
- 원문 링크는 모델이 생성한 URL 대신 메일에서 추출한 URL을 사용한다.
- 완료한 요약을 재사용한다.
- 일시적 오류는 제한적으로 재시도하고, 계속 실패하면 제목·미리보기와 “요약 실패” 표시를 전달한다.

### 설정과 실행

- 비밀값은 `.env`, 발신자 목록과 예약 시간은 설정 파일로 분리한다.
- `.env.example`, 로컬 DB와 비밀값의 Git 제외 규칙, 설치·실행 안내를 제공한다.
- 시작 시 필수 설정을 검사한다.
- 메일이나 GMS 장애가 나더라도 할 일 기능은 유지한다.
- 수집·요약·전달 모듈을 분리해 이후 날씨·공지 등 정보 제공 기능을 추가할 수 있게 한다.
- 공개 HTTP API나 관리 웹 화면은 만들지 않는다.

## 4. 검증과 완료 기준

### 자동 검증

- 할 일 등록·목록·완료·삭제와 잘못된 명령 처리를 검증한다.
- 다른 사용자의 접근 차단을 검증한다.
- 한국 시간 오전 9시 발송과 재시작 후 누락 알림을 검증한다.
- 메일 및 DM 중복 처리를 검증한다.
- HTML·한글·긴 메일 처리를 검증한다.
- GMS 오류·빈 응답·시간 초과를 검증한다.
- Mattermost 재접속과 발송 재시도를 검증한다.
- 외부 서비스는 모의 응답으로 테스트하고, 타입 검사와 빌드를 통과시킨다.

### 실제 연동 확인

실제 계정 설정 후 다음 흐름을 확인하면 완료한다.

1. Mattermost DM에서 할 일 등록 → 목록 조회 → 완료 처리.
2. 테스트 뉴스레터 수집 → GMS 요약 → Mattermost DM 전달.

## 5. 전제와 기본값

- Mattermost에서 본인 아이디·비밀번호 로그인을 사용할 수 있어야 한다. 서버가 추가 인증을 요구하면 현재 인증 코드를 사용한다.
- PC에서 Mattermost REST API와 WebSocket에 접속할 수 있어야 한다.
- 네이버 메일에서 IMAP을 활성화하고 필요한 인증정보를 설정한다.
- 실제 Mattermost 아이디·비밀번호, 메일 인증정보, GMS 키, 뉴스레터 발신자 주소는 사용자가 PC에 설정한다.
- PC가 켜져 있고 프로세스가 실행 중일 때 동작한다.
- 상시 서버 배포, 자연어 할 일 해석, 기타 정보 연동은 후속 범위로 둔다.
